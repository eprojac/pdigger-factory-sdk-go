# Go API conventions

<a id="go-what-is-particular-to-this-sdk"></a>

Use contexts to cancel reads and `range` to consume live streams. The SDK uses the standard library and includes a
fake unit for Go tests.

## One module, the standard library only

The module `github.com/eprojac/pdigger-factory-sdk-go` needs Go 1.23 or newer and nothing outside the standard
library. Its packages: `pdiggerfactory` (the client, the interpreter, replays, streams, the session and the models),
`codec` (the packed maps, bitsets, depth, joints and stone tuples) and `factorytest` (the fake unit).

## Contexts and iterators

Every call takes a `context.Context`: cancelling it ends the call, and for a stream or a replay of a URL it closes the
HTTP connection, even while a read waits on a stalled one. Streams are `iter.Seq2[T, error]` iterators that you
consume with `range`; breaking the loop closes the connection. A stream resumes by itself after a dropped connection
or a restart of the unit, yields an error for an item that does not decode and goes on, and ends after an error it
cannot recover from. A connection that goes silent is left to TCP keepalive (the other languages close one after 30 s
without a byte and resume): put a deadline on the context to bound a wait. `pdiggerfactory.Chan` turns any stream
into a channel for code built on `select`. A `Client` is safe for concurrent use.

## Replays and the core

`OpenReplay` opens a recording file or URL; each of its iterators (`Items`, `Frames`, `Updates`, `Events`,
`Activities`, `TrayFacts`) is one pass with a new interpreter, and `Trays`, `Summary` and `Run` consume a pass for
you. `ReplayOptions` pace a replay in real time (`Pace: PaceRealtime`, at any `Speed`). The interpreter's rules live
in `InterpreterCore`, synchronous and without I/O, which the [high-level tutorial](01-high-level.md) feeds by hand.

## One error type

Every error the SDK returns is, or wraps, a `*pdiggerfactory.Error`, with the HTTP status, a stable `Code` to branch
on, the server's message, the field at fault and the server's `retry_ms`; `pdiggerfactory.AsError` and `errors.As`
find it, and `IsRetryable` says whether it is worth retrying. Reads are retried by themselves on connection errors
and on 429, 502, 503 and 504, with exponential backoff and full jitter (`WithRetries`, `WithBackoff`); a control only
on 429, which the unit sends before it applies anything. Cancellation and deadlines come back as the context's errors:

```go
// Deadlines and cancellation come back as the context's errors.
_, err = client.Interpreter().WaitFor(ctx, pdiggerfactory.AboutStone(999999), 20*time.Millisecond)
fmt.Println("no event about stone 999999 in time:", errors.Is(err, context.DeadlineExceeded))
```

[examples/errors](../../examples/errors/main.go) branches on the codes, and [low-level.md](../low-level.md) lists them.

## The fake unit in your tests

The package `factorytest` is a fake unit that answers the whole API from a recording and the recorded replies, in
process or on a loopback port, with fault injection and a manual clock, so the code you build on the SDK is tested
without a unit, a network or a real clock. [examples/liftcount](../../examples/liftcount/liftcount_test.go) tests a
small package of its own this way:

```go
func TestLifts(t *testing.T) {
	// A fake unit whose session plays the recording embedded in factorytest (aug28 from 21:10.0, one lift); the
	// client talks to it in process.
	fake, err := factorytest.New(factorytest.WithSampleRecording())
	if err != nil {
		t.Fatal(err)
	}
	client, err := pdiggerfactory.New(fake.URL(), pdiggerfactory.WithTransport(fake.Transport()),
		pdiggerfactory.WithClock(factorytest.NewClock(time.Time{})))
	if err != nil {
		t.Fatal(err)
	}
	// Faults: the first stream drops after 20 events, the next connection attempt fails with a 503.
	fake.DropAfter("streamFrames", 20)
	fake.FailNext("streamFrames", 1, factorytest.ErrorReply(503, "busy", "try again"))
```

`WithLiveCamera()` adds the camera `cam-live`, and `make fake-unit` serves the fake on 127.0.0.1 for tools that need
an address, such as these tutorials' programs ([testing.md](../testing.md)).

## Types

There is one Go type per schema of the API, named after it. Parsing is tolerant: fields this version does not know
are ignored, and optional fields are pointers (`pdiggerfactory.Int64` makes one for a parameter), omitted slices or
empty strings. Integers are `int64`, and the `codec` returns `U8Map`s, `Joint`s and `StoneItem`s.
